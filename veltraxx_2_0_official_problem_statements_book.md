## Problem Statement `VTX-T1-01`: Low-Power Configurable ALU with Autonomous Logic BIST (LBIST)

| Field | Specification |
| :--- | :--- |
| **Problem Code** | **`VTX-T1-01`** |
| **Domain Track** | Track 01: Core ASIC & Custom Silicon Architecture (`VLSI-A`) |
| **Organization / Host** | Department of EE-VDT, Sri Shakthi Institute of Engineering and Technology |
| **Category** | Hardware / RTL Design, Design-for-Testability (DFT) & Low-Power VLSI |

### 1. Background & Industry Context
In automotive, aerospace, and mission-critical System-on-Chip (SoC) architectures (such as ISO 26262 ASIL-D compliant controllers), arithmetic execution units cannot rely solely on factory Automated Test Equipment (ATE) to detect silicon defects. Aging effects, electromigration, and latent manufacturing defects require the chip to test itself autonomously during every power-on cycle and idle window using **Logic Built-In Self-Test (LBIST)**. However, traditional single-MISR (Multiple Input Signature Register) architectures suffer from *fault aliasing* (where two faulty bit sequences cancel each other out to produce a valid golden signature) and excessive dynamic switching power during normal idle states.

### 2. Detailed Problem Description
Teams must architect and verify a synthesizable, multi-operation **Arithmetic Logic Unit (ALU)** integrated with an on-chip **Autonomous LBIST Controller**. When `bist_mode = 1`, the system must isolate the ALU from external system buses, automatically feed pseudo-random test vectors generated by a Linear Feedback Shift Register (LFSR), capture the resulting ALU outputs plus status flags (`Zero`, `Carry`, `Overflow`, `Negative`) into a signature compaction engine, and compare the final signature against a hardcoded golden reference to assert `fault_detected` or `test_pass`. During normal functional mode (`bist_mode = 0`), unused arithmetic sub-blocks must be dynamically isolated or clock-gated to minimize dynamic power dissipation.

### 3. Expected System Architecture & Functional Specifications
1. **Core ALU Datapath:** Must support at least 8 distinct arithmetic, logical, and barrel-shift operations with registered inputs/outputs and status flag generation.
2. **LFSR Pattern Generator:** Maximal-length primitive polynomial LFSR generating deterministic pseudo-random operand pairs (`A`, `B`, and `Opcode`) across a configurable number of test clock cycles (e.g., 256 or 1024 cycles).
3. **BIST FSM Controller:** Autonomous state machine (`IDLE -> ISOLATE -> PATTERN_RUN -> COMPARE_SIGNATURE -> REPORT_DONE`) controlled via a single `start_bist` trigger pin.
4. **Fault-Aliasing Reduction & Power Optimization:** Separation of odd/even cycle signatures (Dual-MISR) or bit-swapping LFSR to reduce switching activity and prevent signature aliasing.

### 4. Tiered Evaluation Expectations (Round 1 & Round 2)
* **Tier A (1st & 2nd Year UG — Junior Division):**
  * Synthesizable 8-bit or 16-bit Verilog/SystemVerilog RTL implementation of the ALU, LFSR, BIST FSM, and single MISR.
  * Self-checking testbench demonstrating both normal ALU mode and a simulated stuck-at-0/stuck-at-1 fault injection inside the ALU that triggers `fault_detected = 1`.
* **Tier B (3rd & 4th Year UG, PG & Scholars — Senior Division):**
  * 32-bit pipelined ALU with Dual-MISR (odd/even cycle compaction) and operand isolation / integrated clock-gating (ICG) for low dynamic power.
  * Synthesis PPA (Power, Performance, Area) reports (Cadence Genus / Synopsys Design Compiler / Vivado / Yosys) and Formal Equivalence or fault-coverage analysis.

### 5. Mandatory Slide 5 "Proof of Competence" Artifact (For Round 1 PPT)
Your Slide 5 MUST include: **(a)** The exact primitive polynomial equation used for your LFSR/MISR (e.g., $P(x) = x^{16} + x^{14} + x^{13} + x^{11} + 1$), **(b)** Your BIST Controller FSM state diagram, and **(c)** A preliminary simulation waveform or truth table showing signature divergence under a single stuck-at fault.

## Problem Statement `VTX-T1-02`: Metastability-Hardened Dual-Clock Asynchronous FIFO Bridge

| Field | Specification |
| :--- | :--- |
| **Problem Code** | **`VTX-T1-02`** |
| **Domain Track** | Track 01: Core ASIC & Custom Silicon Architecture (`VLSI-A`) |
| **Organization / Host** | Department of EE-VDT, Sri Shakthi Institute of Engineering and Technology |
| **Category** | Hardware / Clock Domain Crossing (CDC) & SoC Interconnects |

### 1. Background & Industry Context
Modern heterogeneous SoCs contain dozens of independent clock domains—for example, a high-speed 800 MHz processor core communicating with a 50 MHz SPI/UART peripheral bus or a 125 MHz Ethernet MAC. Passing multi-bit counters or data words directly across unrelated clock boundaries causes setup/hold timing violations, resulting in **metastability** where flip-flops oscillate in an indeterminate voltage state and corrupt downstream logic.

### 2. Detailed Problem Description
Teams must design and verify a parameterized, **Metastability-Hardened Dual-Clock Asynchronous FIFO Bridge** capable of streaming burst data safely between an asynchronous Write Clock domain (`wclk`, `wrst_n`) and an independent Read Clock domain (`rclk`, `rrst_n`). The architecture must guarantee zero data loss, zero phantom reads/writes, and glitch-free synchronization of read and write pointers across any frequency ratio (fast-to-slow, slow-to-fast, or irrational clock frequencies).

### 3. Expected System Architecture & Functional Specifications
1. **Dual-Port Memory Array:** Parameterized data width (`DATA_WIDTH`, default 16 or 32 bits) and depth (`ADDR_WIDTH`, $2^N$ locations).
2. **Binary-to-Gray & Gray-to-Binary Pointer Logic:** Because standard binary counters change multiple bits simultaneously (e.g., `0111` to `1000` flips 4 bits at once), read and write pointers must be converted into **Gray Code** (where only 1 bit changes per increment) before crossing clock boundaries.
3. **Multi-Stage Flip-Flop Synchronizers:** 2-stage (or configurable 3-stage) D-flip-flop synchronizer chains transferring Gray-coded pointers across `wclk` and `rclk`.
4. **Full, Empty & Programmable Watermark Generation:** Accurate generation of `wfull`, `rempty`, `almost_full`, and `almost_empty` flags using MSB/2nd-MSB Gray pointer comparison logic.

### 4. Tiered Evaluation Expectations (Round 1 & Round 2)
* **Tier A (1st & 2nd Year UG — Junior Division):**
  * Synthesizable Verilog RTL for an 8-bit or 16-bit deep Asynchronous FIFO with Gray-code conversion and 2-stage synchronizers.
  * Dual-clock testbench demonstrating burst write until `wfull = 1` and burst read until `rempty = 1` across two unrelated clock periods (e.g., $T_{wclk} = 7\text{ ns}$ and $T_{rclk} = 13\text{ ns}$).
* **Tier B (3rd & 4th Year UG, PG & Scholars — Senior Division):**
  * Parameterized RTL supporting non-power-of-two depths or dynamic programmable `almost_full` / `almost_empty` thresholds, plus asynchronous reset assertion / synchronous de-assertion circuits (`reset_sync`).
  * Static Timing Analysis (STA) constraints (`set_false_path` / `set_max_delay` on CDC paths) and synthesis reports proving MTBF (Mean Time Between Failures) resilience.

### 5. Mandatory Slide 5 "Proof of Competence" Artifact (For Round 1 PPT)
Your Slide 5 MUST include: **(a)** A complete block diagram showing the exact `wclk` and `rclk` domain boundary line, **(b)** The exact boolean/XOR equation used to detect the **Full Condition** in Gray code (comparing the top two MSBs vs. remaining bits), and **(c)** Preliminary dual-clock simulation waveforms.

## Problem Statement `VTX-T1-03`: Fault-Tolerant 5-Port Network-on-Chip (NoC) Mesh Router

| Field | Specification |
| :--- | :--- |
| **Problem Code** | **`VTX-T1-03`** |
| **Domain Track** | Track 01: Core ASIC & Custom Silicon Architecture (`VLSI-A`) |
| **Organization / Host** | Department of EE-VDT, Sri Shakthi Institute of Engineering and Technology |
| **Category** | Hardware / Multi-Core Interconnects, NoC & Fault-Tolerant Silicon |

### 1. Background & Industry Context
As AI accelerators and multi-core processors scale beyond 8 to 64 cores on a single die, traditional shared buses (like AXI crossbars) become wiring bottlenecks due to capacitive loading and arbitration stalls. Industry chips use packet-switched **Network-on-Chip (NoC)** mesh routers. However, at deep sub-micron nodes, crosstalk and cosmic-ray single-event upsets (SEUs) flip bits inside router buffers, causing **Silent Data Corruption (SDC)** or deadlocked packets routed to the wrong core.

### 2. Detailed Problem Description
Teams must design a synthesizable **5-Port Network-on-Chip (NoC) Mesh Router** (`North`, `South`, `East`, `West`, and `Local PE Core` ports) that routes flits/packets across a 2D mesh coordinate grid `(X, Y)` without deadlock, while actively detecting and recovering from bit-flip corruptions inside the packet header and payload.

### 3. Expected System Architecture & Functional Specifications
1. **Packet/Flit Structure:** Defined packet format containing `Header` (Source X/Y, Destination X/Y, Packet ID) + `Payload` + `Error Check Code (ECC / Parity)`.
2. **Deadlock-Free XY Routing Engine:** Compares current router coordinates `(X_curr, Y_curr)` with target coordinates `(X_dest, Y_dest)`—routing horizontally (`East`/`West`) first until `X_curr == X_dest`, then vertically (`North`/`South`), and finally ejecting at `Local`.
3. **Round-Robin / Priority Switch Allocator:** Fair arbitration when two input ports simultaneously request the same output port (preventing port starvation).
4. **Silent Data Corruption (SDC) Guard:** Hardware parity or Hamming SEC-DED (Single Error Correction, Double Error Detection) encoder/decoder on router links with automatic single-bit correction or `NACK` retransmission request.

### 4. Tiered Evaluation Expectations (Round 1 & Round 2)
* **Tier A (1st & 2nd Year UG — Junior Division):**
  * Synthesizable RTL for a 5-port router with input FIFO buffers, deterministic XY routing engine, 5x5 crossbar switch, and even/odd parity error detection flag.
  * Simulation testbench sending packets simultaneously across multiple ports to different `(X, Y)` coordinates.
* **Tier B (3rd & 4th Year UG, PG & Scholars — Senior Division):**
  * Wormhole switching with Virtual Channel (VC) flow control (`credit/valid` handshaking), Round-Robin arbiter, and Hamming SEC-DED single-bit hardware auto-correction on every flit.
  * Synthesis area/timing breakdown and latency-vs-injection-rate throughput analysis.

### 5. Mandatory Slide 5 "Proof of Competence" Artifact (For Round 1 PPT)
Your Slide 5 MUST include: **(a)** The exact bit-level packet/flit frame layout (e.g., 32-bit flit field bit-positions), **(b)** The XY routing decision truth table, and **(c)** The arbiter priority state diagram or Hamming parity matrix.

## Problem Statement `VTX-T1-04`: Dynamic Clock-Gated Multi-Master APB/AXI-Lite Peripheral Interconnect

| Field | Specification |
| :--- | :--- |
| **Problem Code** | **`VTX-T1-04`** |
| **Domain Track** | Track 01: Core ASIC & Custom Silicon Architecture (`VLSI-A`) |
| **Organization / Host** | Department of EE-VDT, Sri Shakthi Institute of Engineering and Technology |
| **Category** | Hardware / AMBA SoC Protocols & Low-Power Clock Gating |

### 1. Background & Industry Context
In battery-powered IoT SoCs and wearables, the clock tree accounts for 35% to 50% of total dynamic power dissipation ($P_{dyn} = \alpha \cdot C \cdot V_{DD}^2 \cdot f$). Even when low-speed peripherals (UART, SPI, I2C, PWM, Watchdog Timer) are not actively being addressed by the CPU, their internal registers continue toggling on every clock edge unless an intelligent **Peripheral Bus Interconnect** dynamically gates their clocks and isolates their data buses.

### 2. Detailed Problem Description
Teams must architect an **AMBA-Compliant Peripheral Interconnect & Power-Aware Bridge** that connects one or more bus masters to at least 4 memory-mapped peripheral slaves, automatically enabling the clock (`PCLK_gated[i]`) ONLY for the specific peripheral slave addressed during an active bus transaction, while keeping all idle slaves in a zero-toggle clock-gated sleep state. Furthermore, the bridge must include a hardware **Bus Watchdog Timeout Counter** so a hung peripheral (`PREADY` stuck at `0`) never freezes the entire processor bus.

### 3. Expected System Architecture & Functional Specifications
1. **Address Decoder & Memory Map:** Clean address decoding mapping distinct base address ranges (e.g., `0x4000_0000` for Slave 0, `0x4000_1000` for Slave 1) to `PSELx` select lines.
2. **Glitch-Free Integrated Clock Gating (ICG) Cell:** Negative-level latch + AND gate structure (`latch_en` sampled when `CLK = 0`) preventing runt clock pulses or glitches on `PCLK_gated[0:3]`.
3. **AMBA Handshake FSM (`IDLE -> SETUP -> ACCESS`):** Full compliance with `PSEL`, `PENABLE`, `PWRITE`, `PREADY`, and `PSLVERR` timing rules.
4. **Hardware Bus Watchdog:** Configurable cycle counter (e.g., 16 or 32 cycles) that asserts `PSLVERR = 1` and terminates the transaction if a slow or faulty slave fails to assert `PREADY`.

### 4. Tiered Evaluation Expectations (Round 1 & Round 2)
* **Tier A (1st & 2nd Year UG — Junior Division):**
  * Synthesizable APB Master-to-4-Slave interconnect with memory-mapped address decoding, glitch-free clock gating per slave, and working read/write simulation waveforms.
* **Tier B (3rd & 4th Year UG, PG & Scholars — Senior Division):**
  * AXI4-Lite-to-APB protocol bridge (converting decoupled AXI read/write channels into APB transfers) OR 2-Master arbitrated APB interconnect with bus watchdog timeout recovery and synthesized dynamic power savings comparison (Ungated vs. Clock-Gated).

### 5. Mandatory Slide 5 "Proof of Competence" Artifact (For Round 1 PPT)
Your Slide 5 MUST include: **(a)** The memory-map address decoding table for all slaves, **(b)** The schematic/RTL of your glitch-free Latch+AND clock-gating cell explaining why a bare AND gate causes clock glitches, and **(c)** An APB timing diagram showing `PCLK_gated` waking up only during `PSEL=1`.

## Problem Statement `VTX-T1-05`: Side-Channel Resistant Cryptographic Datapath (Masked Cipher)

| Field | Specification |
| :--- | :--- |
| **Problem Code** | **`VTX-T1-05`** |
| **Domain Track** | Track 01: Core ASIC & Custom Silicon Architecture (`VLSI-A`) |
| **Organization / Host** | Department of EE-VDT, Sri Shakthi Institute of Engineering and Technology |
| **Category** | Hardware Security, Cryptographic Silicon & Side-Channel Countermeasures |

### 1. Background & Industry Context
Even when an encryption algorithm (such as AES-128, PRESENT-80, or Post-Quantum NTT) is mathematically unbreakable, physical silicon implementations leak their secret keys through **Side-Channel Attacks (SCA)**. By placing a resistor on the chip's $V_{DD}$ power pin and measuring micro-ampere current spikes with an oscilloscope (**Differential Power Analysis - DPA**), an attacker can deduce the secret key within minutes because standard CMOS logic consumes power proportional to the Hamming distance ($0 \rightarrow 1$ transitions) of the secret data.

### 2. Detailed Problem Description
Teams must design a hardware cryptographic datapath (e.g., an AES S-Box/SubBytes engine, PRESENT lightweight block cipher, or Simon/Speck core) fortified with **Boolean Masking / Power-Flattening Countermeasures**. By splitting sensitive internal state variables into random shares ($x = x_0 \oplus m$, where $m$ is a fresh pseudo-random mask generated on-chip), the instantaneous switching activity of the circuit becomes statistically independent of the secret key.

### 3. Expected System Architecture & Functional Specifications
1. **Baseline Cryptographic Core:** Synthesizable RTL encryption datapath with standard key-schedule and round transformation logic.
2. **On-Chip PRNG Mask Generator:** High-entropy LFSR / Cellular Automata PRNG supplying fresh random mask bits on every clock cycle.
3. **First-Order Masked Non-Linear Layer (S-Box / AND Gate):** Implementation of masked logic gates (e.g., Trichina AND gate or Domain-Oriented Masking with pipeline synchronization flip-flops to prevent glitch leakage).
4. **Toggle-Count / Hamming-Weight Analyzer Testbench:** A verification module that counts total bit-flips (`toggle_count`) per encryption round across different keys to prove reduced correlation between key bits and switching activity.

### 4. Tiered Evaluation Expectations (Round 1 & Round 2)
* **Tier A (1st & 2nd Year UG — Junior Division):**
  * Synthesizable RTL of a lightweight cipher (PRESENT-80 or 4-bit/8-bit S-Box datapath) with basic XOR input/output masking and a self-checking encryption/decryption testbench.
* **Tier B (3rd & 4th Year UG, PG & Scholars — Senior Division):**
  * First-order Boolean-masked AES S-Box or lightweight cipher with pipelined register barriers (preventing combinational glitch un-masking) and quantitative comparison of switching activity / power reports between the Unmasked vs. Masked RTL.

### 5. Mandatory Slide 5 "Proof of Competence" Artifact (For Round 1 PPT)
Your Slide 5 MUST include: **(a)** The mathematical Boolean masking equation showing how non-linear operations ($A \cdot B$) are computed on masked shares without recombining the secret, and **(b)** Gate-level schematic or RTL interface of the masked S-Box/cipher block.

## Problem Statement `VTX-T2-01`: Real-Time 2D Sobel & Canny Edge-Detection Streaming Pipeline

| Field | Specification |
| :--- | :--- |
| **Problem Code** | **`VTX-T2-01`** |
| **Domain Track** | Track 02: FPGA Acceleration & Reconfigurable Hardware (`VLSI-B`) |
| **Organization / Host** | Department of EE-VDT, Sri Shakthi Institute of Engineering and Technology |
| **Category** | FPGA Vision Acceleration, Streaming DSP & RTL Image Processing |

### 1. Background & Industry Context
Autonomous drones, high-speed industrial sorting cameras, and ADAS lane-keeping systems require real-time edge detection at 60 to 120 frames per second (FPS). Executing 2D spatial convolutions in software on an embedded CPU introduces massive frame latency and DRAM bandwidth bottlenecks because every pixel requires fetching a $3 \times 3$ neighborhood from external memory.

### 2. Detailed Problem Description
Teams must architect a **Zero-Frame-Buffer Streaming 2D Edge-Detection Hardware Accelerator** in Verilog/SystemVerilog/VHDL. Instead of storing an entire image in external RAM, the hardware must ingest 1 grayscale pixel per clock cycle via an AXI-Stream / valid-ready interface, buffer exactly 2 previous image rows inside on-chip **Line Buffers (Shift Registers / Dual-Port BRAM)**, compute horizontal ($G_x$) and vertical ($G_y$) spatial gradients in parallel using shift-and-add arithmetic, and output a binary or gradient-magnitude edge pixel on every single clock cycle after initial pipeline fill.

### 3. Expected System Architecture & Functional Specifications
1. **3x3 Sliding Window Line-Buffer Architecture:** Two cascaded row-length FIFO/BRAM line buffers feeding a $3 \times 3$ shift-register pixel matrix (`P00` to `P22`) simultaneously every clock cycle.
2. **Multiplier-Free Pipelined Gradient Engine:** Computation of $G_x = (P_{02} + 2P_{12} + P_{22}) - (P_{00} + 2P_{10} + P_{20})$ and $G_y$ using strictly hardware bit-shifts (`<< 1`) and adders (zero costly multipliers), followed by fast Manhattan magnitude approximation ($|G| \approx |G_x| + |G_y|$).
3. **Dynamic Thresholding & Border Handling:** Programmable hysteresis/threshold comparator with image boundary padding logic.

### 4. Tiered Evaluation Expectations (Round 1 & Round 2)
* **Tier A (1st & 2nd Year UG — Junior Division):**
  * RTL implementation of the $3 \times 3$ sliding window line buffer and Sobel gradient calculator.
  * Simulation testbench that reads a standard test image converted to a `.hex` / `.mem` file, runs it through the Verilog simulator, and reconstructs the output `.hex` into a visible edge-detected image.
* **Tier B (3rd & 4th Year UG, PG & Scholars — Senior Division):**
  * Full streaming pipeline incorporating Gaussian smoothing pre-filter + Sobel gradient + directional Non-Maximum Suppression (Canny pipeline), synthesized for FPGA (Vivado / Quartus) with LUT/BRAM/Fmax utilization reports or live hardware output.

### 5. Mandatory Slide 5 "Proof of Competence" Artifact (For Round 1 PPT)
Your Slide 5 MUST include: **(a)** The hardware block diagram of the 2-row Line Buffer feeding the 9-register $3 \times 3$ window, **(b)** Pipeline latency calculation (in clock cycles for a $W \times H$ image), and **(c)** Preliminary input-vs-output pixel matrix verification.

## Problem Statement `VTX-T2-02`: Custom RISC-V (RV32I) Core with Hardware AI/DSP Instruction Extension

| Field | Specification |
| :--- | :--- |
| **Problem Code** | **`VTX-T2-02`** |
| **Domain Track** | Track 02: FPGA Acceleration & Reconfigurable Hardware (`VLSI-B`) |
| **Organization / Host** | Department of EE-VDT, Sri Shakthi Institute of Engineering and Technology |
| **Category** | Processor Architecture, RISC-V ISA Customization & Hardware Accelerators |

### 1. Background & Industry Context
The open-source **RISC-V Instruction Set Architecture (ISA)** has revolutionized custom silicon because it reserves dedicated instruction encoding spaces (`custom-0` opcode `0x0B` and `custom-1` opcode `0x2B`) for domain-specific hardware acceleration. On a standard microcontroller, running a neural network dot-product ($acc \leftarrow acc + (A \times B)$) or quantized activation function takes 15 to 40 clock cycles per element in software. Adding a custom hardware execution unit directly inside the RISC-V pipeline collapses that loop into a **single clock cycle**.

### 2. Detailed Problem Description
